<h1 align="center">tg-hydrus-import-bot</h1>

<p align="center"><b>Бот для Telegram, позволяющий проводить импорт в Hydrus Network, посредством самого мессенджера.</b></p>

Обращаясь к боту внутри Телеграма, можно сохранять в своём запущенном экземпляре [Гидруса](https://github.com/hydrusnetwork/hydrus) изображения, видео, аудио, голосовые и видеосообщения (кружочки), а также документы.<br>
К тому же бот пытается импортировать в Гидрус отправляемые ссылки, как если бы импорт проводился непосредственно в клиенте Гидруса. Также контент, полученный ссылками, возвращается ответным сообщением.<br>
Сопутствующие хештеги также обрабатываются как теги к присланному контенту (нижнее подчёркивание заменяется пробелом, концом тега считается символ перед пробелом).

#### Команды
---
* `/start`, `/help` — показать справку по командам
* `/to_tags` — показать теги, извлечённые из хештегов в сообщении
* `/to_hashtags` — преобразовать построчный список тегов в хештеги
* `/sauce_by_hash <хэш>...` — найти источники через SauceNAO и импортировать их
* `/tags_by_hash <хэш>...` — показать теги файлов по хэшам
* `/hashtags_by_hash <хэш>...` — показать хештеги файлов по хэшам
* `/get_hash` — отправить в подписи к фото, чтобы получить хэш файла, если он уже есть в Hydrus

Команды SauceNAO работают, только если задан `SAUCENAO_TOKEN`.

## Запуск
После скачивания репозитория запустите бот один раз — в папке появится `.conf.json` и установите [настройки](#файл-настроек).<br>
Обязательно установите зависимости в ваше окружение python: `python -m pip install -r requirements.txt`<br>
Перед запуском бота убедитесь, что у вас запущен [Hydrus Network](https://github.com/hydrusnetwork/hydrus), а также создан токен с [нужными правами](#права-доступа-hydrus).<br>
Команда `python tg-hydrus-import-bot` в каталоге репозитория запустит бота, после чего сразу можно заниматься импортом.

#### Файл настроек
---
**Файл настроек располагается в рабочей директории, носит имя `.conf.json` и может редактироваться прямо в блокноте**<br>
Настройки:
* `LOG_LEVEL`: уровень логирования, допустимые значения: `TRACE`, `DEBUG`, `INFO`, `SUCCESS`, `WARNING`, `ERROR`, `CRITICAL`
* `LOG_PATH`: путь к файлу лога
* `TG_ADMIN_ID`: <u>список</u> идентификаторов пользователей Телеграма, кому разрешено отправлять контент в ваш экземпляр Гидруса. Обратите внимание, что это именно список, поэтому все числовые идентификаторы должны быть перечислены внутри квадратных скобок.
* `TG_BOT_TOKEN`: токен телеграм-бота, берётся при создании бота у [@BotFather](https://t.me/BotFather)
* `TG_PROXY`: прокси для Telegram Bot API, например `http://127.0.0.1:8118` или `socks5://127.0.0.1:1080`. Если пусто, бот использует `HTTPS_PROXY`/`ALL_PROXY`, а затем системный прокси Windows
* `HYDRUS_TOKEN`: токен Hydrus API, берётся в клиенте: services -> review services -> local -> client api -> add
* `HYDRUS_API_URL`: адрес Hydrus API, по умолчанию `http://127.0.0.1:45869/`
* `ALLOW_INSECURE_HYDRUS`: разрешить HTTP к Hydrus не на localhost. По умолчанию `false`: токен Hydrus не должен передаваться по сети без шифрования
* `DUPLICATE_MAX_DISTANCE`: максимальное расстояние перцептивного хэша изображения, при котором файл считается похожим дубликатом. По умолчанию `5`, значение `0` оставляет только точное совпадение перцептивного хэша
* `TIME_TO_SLEEP`: время в секундах, которое ожидает программа в случае сбоя
* `TAGS_NAMESPACE`: пространство тегов Гидруса, в которое эти теги и записываются
* `DESTINATION_PAGE_NAME`: название страницы в клиенте Гидруса, на которую отправляются импортированные файлы
* `TEMP_PATH`: путь к папке временных файлов; бот создаёт и очищает внутри неё подкаталог `tg-hydrus-import-bot`, не затрагивая остальное содержимое
* `CONTENT_TYPES`: типы контента, которые бот будет обрабатывать, допустимые типы: `[ "photo", "video", "animation", "video_note", "audio", "voice", "document", "text" ]`
* `SAUCENAO_TOKEN`: токен SauceNAO; если не задан, команды поиска источников отключены

Также секреты (*_TOKEN) можно задать через переменные окружения, в таком случае они имеют приоритет перед файлом настроек.

В `LOG_PATH` и `TEMP_PATH` раскрываются переменные окружения и `~`: например, `%TEMP%` в Windows, `$TEMP` в Linux/macOS или `~/.cache`. Относительные пути по-прежнему считаются от рабочей директории. Внутри `TEMP_PATH` бот использует подкаталог `tg-hydrus-import-bot`, поэтому указывать его в настройке отдельно не нужно.

Приоритетные домены для дедупликации задаются отдельным файлом `duplicate_domains.txt` в рабочей директории. Скопируйте `duplicate_domains.example.txt` и перечислите домены по одному на строку; пустые строки и текст после `#` игнорируются, поддомены считаются частью домена. Файл `duplicate_domains.txt` не попадает в git.

#### Дубликаты
---
Точные дубликаты (совпадает sha256) повторно не импортируются: бот добавляет теги существующему файлу и сообщает, что файл уже есть в базе. Для загружаемых изображений дополнительно проверяется перцептивное расстояние 0: если новый файл не больше существующего по ширине и высоте, он тоже считается точным дубликатом. Для видео, аудио и документов перцептивного поиска нет — используется только sha256.

Если найден похожий файл с расстоянием больше 0 или новый файл лучше существующего, бот показывает оба файла и клавиатуру:
* «Оставить первый (существующий)» — новый файл не импортируется, теги добавляются существующему;
* «Оставить второй (новый)» — новый файл импортируется, существующий удаляется с сохранением связи дубликата;
* «Оставить оба — альтернативы» — файлы остаются как альтернативы;
* «Оставить оба — не связаны» — файлы остаются без связи дубликатов.

При импорте по ссылке Hydrus сам связывает ссылку с существующим файлом при точном совпадении. Для видео, аудио и документов этим проверка и ограничивается: перцептивного поиска для них нет. Если появился новый файл-изображение с перцептивным расстоянием 0, бот ищет похожие файлы по хэшу уже добавленного изображения — без скачивания содержимого — и применяет приоритет доменов: существующий файл с приоритетной ссылкой сохраняется, а если приоритетна только новая ссылка — сохраняется новый файл. В остальных случаях показывается клавиатура выбора.

Если Hydrus помнит ссылку, но файла уже нет (после чистого удаления), обычный `add_url` на существующую страницу не переобрабатывает её. В этом случае бот создаёт отдельную страницу `HC reimport <дата>` и повторяет импорт на ней. Такие страницы остаются в клиенте Hydrus, поэтому после успешного импорта их можно закрыть вручную.

#### Права доступа Hydrus
---
**Для корректной работы бота необходимо токену выставить права**<br>
После каждого права указано, для чего оно нужно
* `edit file tags` : 
  * `/get_service` - получение внутреннего ключа пространства тегов
  * `/add_tags/clean_tags` - преобразование тегов к «чистому» виду
  * `/add_urls/add_url` - добавление тегов сразу при импорте контента по ссылке
  * `/add_tags/add_tags` - добавление тегов
* `import and delete files` : 
  * `/add_files/add_file` - загрузка файлов в Гидрус
* `import and edit urls` : 
  * `/add_urls/get_url_files` - проверка статуса существования контента по ссылке (необходимо для проставления новых тегов существующему файлу)
  * `/add_urls/add_url` - импорт контента по ссылке
  * `/add_urls/associate_url` - приписывание ссылки к загруженному в Гидрус файлу обычным способом
* `manage pages` : 
  * `/manage_pages/get_pages` - получение списка страниц в клиенте для поиска нужной
  * `/manage_pages/add_files` - помещение импортированного файла на страницу в клиенте
  * `/manage_pages/new_page` - создание страницы повторного импорта, если Hydrus помнит ссылку, но файла уже нет
* `search and fetch files` : 
  * `/get_files/file` - непосредственное получение скачанного по ссылке файла для отправки в ответ
  * `/get_files/file_metadata` - получение тегов файла по хэшу
* `manage file relationships` :
  * `/manage_file_relationships/get_file_relationships` - поиск главного файла (king) для дубликатов, чтобы возвращать его теги и содержимое

Непредоставление токену этих прав урежет возможности бота на вышеперечисленные.

Команды, которым нужно определить king (`/sauce_by_hash`, `/tags_by_hash`, `/hashtags_by_hash`,
отправка контента по ссылкам), требуют одновременно `search and fetch files` и
`manage file relationships`. Без второго права они не подменяют king исходным хэшем,
а сообщают об ошибке или отсутствии результата.

## Тесты
---
Тесты используют стандартный `unittest`. Основная часть работает на моках и не требует внешних сервисов:
```
python run_tests.py
```
Интеграционные тесты автоматически запускаются, если Hydrus и Telegram доступны; если сервис недоступен, соответствующие тесты пропускаются.
Для принудительного запуска (недоступность считается ошибкой) задайте `RUN_INTEGRATION=1`:
```
RUN_INTEGRATION=1 python run_tests.py
```
В PowerShell:
```
$env:RUN_INTEGRATION='1'; python run_tests.py
```
Чтобы отключить интеграционные тесты:
```
SKIP_INTEGRATION=1 python run_tests.py
```
